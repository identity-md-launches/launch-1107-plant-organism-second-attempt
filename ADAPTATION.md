# Launch 1003 adaptation — PLANT ORGANISM

This revision deploys only `PlantOrganism` on Robinhood Chain (4663), with the existing nonpayable static constructor types `(address,address,bytes32,address,uint32,address)`. IMD, Intake, action and signer addresses are unchanged. The explicit deployer remains `$owner`, so factory deployment cannot trap the one-time bind privilege. No transaction was broadcast, dependency installed, build configuration changed, or additional application introduced.

## Reproduction and changes

The original `forge test --offline` passed all 102 tests. Four supplied proofs were copied to `test/scratch/` and run against the original source: all four failed their safety assertions with the reported behavior (flash placement, no settlement after three silent requests, remaining supply unable to move, ERC-1271 constructor rejection). Original assumption tests also accepted a 400-day-old rotation signature and a 9000 IMD fee pull. These are concrete reproductions, not findings inferred from patterns.

## Preserved behavior and audit scope

`7a8ae6172e97` is a trust assumption, not a reproduced defect: the brief expressly retains deployer-only, once-only `bind`. Binding still requires the future hook/token; the fixed-supply exact-transfer PLANT requirement and pre-bind donation lock are documented and tested. No substitute hook/token or invented deployment address is introduced.

`548fd26561a9` is a historical coverage report, not an actionable finding. This revision does not claim its live RPC observations remain current. All six actionable audit defects reproduced; none was dismissed as non-reproducing. The partial-day item is an explicitly requested behavior change; the remaining informational items are addressed above.

`src/WeatherQuestion.sol` is byte-for-byte unchanged: oracle question and request body remain exact. Hours, sips, water, pot/backing/owed conservation, bounty, redemption, dead-plant exits, callback storage-only behavior, and once-only binding are preserved. `README.md` is condensed to one page of operating guidance, including signer-envelope encoding and trust assumptions. `DEPENDENCIES.md` records the verifier hook extraction. Build configuration and vendored dependencies are untouched. No admin/upgrade/pause, delegatecall/callcode/selfdestruct, proxy or extra launch contract is added.

## Validation

`forge build` passed with the unchanged project configuration (Foundry lint warnings remain). `forge test` passed: **113 tests across 15 suites, zero failures or skips**. This includes 1000-run arithmetic fuzz tests and both state machines (128×64 and 256×96 calls, zero reverts). Runtime is **21,173 bytes**, below EIP-170; constructor/initcode and forbidden-opcode checks passed, as did cold 200k callbacks and 400k settlements, including the third timeout with a move and advance repayment. Manifest shape, preserved dependency arguments, untouched build/dependency paths, and byte-for-byte weather source were also checked. A shared test-fixture impersonation error found on the first revised run was repaired before the final passing run. No Slither, Mythril, live RPC integration or deployment was run. Live Intake behavior, token/hook suitability and live token gas remain launch-service integration responsibilities.
